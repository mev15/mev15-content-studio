# 自动版式系统

只使用一套 Twitter 账号壳 + 青十五 Swiss 内容系统：顶部固定显示头像、昵称、蓝 V、`@handle` 和更多菜单；内容区使用暖白纸面、深色正文、单一蓝色强调、严格左对齐和清晰字号反差。不要让用户选择主题。

## 自动选择

- 开场钩子：`cover`。
- 一个反常识结论：`statement`。
- 并列条件、建议或坑点：`list`。
- 有明确先后关系：`steps`。
- 两种方式、优缺点或前后差异：`compare`。
- 强判断或个人结论：`quote`。
- 原文有关键截图或证据图：`image`。
- 工具名、官网与界面截图同时出现：`tool`；同组工具必须复用同一标题层级和图片结构。
- 最终可执行结论：`summary`。

连续两页不要使用同一种版式，除非内容确实需要。整组至少出现三种页面角色。

## 内容节奏

推荐序列：

```text
cover → statement/list → steps/compare → image/list → quote/summary
```

- 封面只承诺读者能得到什么，不塞文章目录。
- 第二页快速交付结论，避免继续铺背景。
- 中间页用证据、步骤或对比展开。
- 最后一页收束为可以记住或执行的 2–4 点。
- 最后一页若是工具选择清单，在相应条目旁复用前文官方图标，帮助读者快速对应；连接方式、方法论等非工具项保持纯文字。

## 图像规则

- 只在图片能证明观点时使用 `image`。
- 按文章顺序识别图片，并严格执行用户给出的“从某章节开始保留”“某章节之前不用”等边界。
- 用户要求尽量带原图时，优先为关键产品界面、流程架构和操作截图安排独立图片页；不要用重新绘制或文字复述替代可用原图。
- 截图必须保留关键文字可读性；一页最多一张主截图。
- 没有合适图片就用纯排版页，不生成装饰性配图填空。

## 文案保真规则

- 先删除次要句，再截短长句，最后才做必要改写。
- 保留作者的第一人称、判断强度、产品名称和具体用法。
- 不把“我使用的方式”改写成无来源的普遍结论。
- 页面标题可从原文小标题、加粗句或段首结论中提取；原文 `**粗体**` 与 `==高亮==` 原样进入故事板，用于渲染重点；避免重新发明更像营销文案的说法。

## 密度规则

- 一页信息不足时与相邻观点合并，不用空洞装饰撑满。
- 连续两页若属于“结论 + 同一结论的步骤/示意图”，先尝试组合成一张高容量页；只有合并后正文、图片和层级仍清楚时才保留，不能为了语义连续牺牲手机可读性。
- 一页信息过多时删去解释性文字，保留结论和证据，不缩小全局字号。
- 大标题、列表行和数字承担视觉密度；留白服务于层级，不形成无理由的大块空带。
- 页数是上述判断的结果，不是排版目标；禁止先指定固定张数再反向拉伸留白、缩字或切断上下文。
