# 交付前检查

- 封面缩到手机宽度后，标题仍能一眼读完。
- 每页能用一句话说清它的唯一任务。
- 连续两页如果在解释同一件事，已经合并或能说明必须拆页的容量原因。
- 没有为了达到某个固定张数而拉伸留白、缩小文字、裁小图片或机械拆分内容。
- 整组不是重复的“标题 + 文本框”，至少使用三种页面角色。
- 正文和列表在手机上清晰，不靠缩小字号塞内容。
- 列表序号、首行和说明文字对齐。
- 没有无理由的大块底部留白，也没有为了填满而添加的假标签或装饰。
- 图片与截图不变形，关键 UI 和文字没有被裁掉。
- Twitter 壳完整显示头像、昵称、蓝 V、`@handle` 与更多菜单，且不与内容标题争抢层级。
- 用户要求保留的原图都已出现，明确排除的章节图片没有进入卡片。
- 压缩文案主要由原句删减与合并得到，没有把个人经验改成泛化教程或营销话术。
- 原文 `**粗体**` 与 `==高亮==` 在卡片中分别呈现为明确的粗体和荧光笔效果，没有丢失或错误扩大强调范围。
- 同组工具介绍页使用相同的“官方图标 + 工具名 + 高亮官网 + 原文截图”结构；图标来源可核实，缺图时使用字标而非第三方素材。
- 工具选择型收束页已复用对应官方图标，图标与工具名一一匹配，非工具项没有误配图标。
- 已先查看整组节奏，再逐张查看所有图片页、工具页和信息密集页原图；不能只凭缩略图判断字号与裁切。
- 所有事实、数字、产品名和个人经历都能回到原文。
- 最后一页给出明确结论，不写空泛 CTA。
- `validation.json` 中 `ok` 为 `true`。
