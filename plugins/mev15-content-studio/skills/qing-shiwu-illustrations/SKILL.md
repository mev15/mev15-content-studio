# 青十五怪诞正文配图与文章封面

## 核心定位

为中文文章设计和生成 16:9 横版正文配图，以及同一视觉概念下的微信公众号头条/次条、X Articles 和知乎文章封面。目标不是做商业插画、PPT 信息图或可爱卡通，而是把文章里的关键判断、流程、结构、状态或隐喻，变成清爽、怪诞、有创意、可读但不说明书的手绘解释图。

默认视觉 IP 是“青十五”：纯白圆润的大头与上半身连成一体，黑色不规则轮廓，左右不对称的黑色点眼和短斜眉，配两条细手臂。每次只画上半身，不画腰部以下、腿或完整站立身体。青十五必须用手臂、视线和上半身姿态参与画面的核心动作，不能只是站在旁边当装饰。

## 先读这些参考

按任务需要读取，不要一次塞满上下文：

- `references/style-dna.md`：风格 DNA、颜色、文字、禁忌。
- `references/qing-shiwu-ip.md`：青十五 IP 的形象、性格、动作库和禁忌；涉及生图或改图时必须读取。
- `references/composition-patterns.md`：结构类型、原创隐喻方法和反复刻规则。
- `references/prompt-template.md`：单张生图提示词模板。
- `references/qa-checklist.md`：生成后检查和迭代规则。
- `references/article-marker-workflow.md`：指定 Markdown 文章时的默认标记识别、生图、保存和安全插入规则；处理文章文件时必须读取。
- `references/multi-platform-cover-workflow.md`：封面概念、母版、平台尺寸、智能裁切、X 超宽适配和保存规则；涉及封面时必须读取。
- `assets/ip-reference/qing-shiwu-avatar.jpg`：每次生图或改图都必须传入的角色参考图；只参考角色身份，不要默认复制图中手持的水果。
- `assets/ip-reference/qing-shiwu-avatar.svg`：用于核对精确轮廓和五官关系，不作为默认生图输入。

## 工作流

### 0. 先路由任务

先根据用户意图路由；明确的封面要求优先于默认文章标记扫描。

- 用户明确提到“封面 / cover / 公众号 / X Articles / Twitter Articles / 知乎 / 三平台封面 / 多平台封面 / 平台适配”时，读取 `references/multi-platform-cover-workflow.md`，进入“多平台封面模式”。只生成封面，不扫描或替换正文配图标记，除非用户同时明确要求两者。
- 多平台封面模式是一次 Skill 调用完成全部资产，不等于只调用一次生图模型。先建立一个统一视觉概念；公众号和知乎优先由母版裁切，X 超宽版无法安全裁切时使用同一概念重新排版。
- 只收到 Markdown 文章路径、没有明确封面要求时，读取 `references/article-marker-workflow.md` 并扫描全文中的独立配图标记。
- 找到标记，且用户没有禁止生图或修改文章：默认进入“文章标记模式”，逐个结合全文生成图片，保存资产，用相对 Markdown 图片链接替换成功处理的标记。
- 没有找到标记：报告未发现可识别标记，不要擅自选择插图位置或修改文章；用户另有明确生图要求时，再按普通工作流执行。
- 用户明确说“只规划 / 先不要生图 / 不要修改文章 / 只生成不插入”时，始终服从用户指令，不要启动对应的默认动作。
- 用户明确指定输出目录、文件名、标记格式或插入格式时，优先采用用户指定值。

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。提炼：

- 核心观点是什么
- 哪些段落承担认知转折
- 哪些内容适合用图解释
- 哪些地方只适合文字，不需要图

不要平均配图。优先选择“认知锚点”，例如：核心判断、两个断点、输入输出闭环、分流、前后对比、一鱼多吃、承接路径、常见坑、角色状态变化。

### 2. 先出配图策略

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 青十五在图里用上半身和手臂做什么
- 建议元素
- 建议中文标注词

默认 4-8 张。文章很短时 1-3 张；长文也不要轻易超过 9 张。够用就好，避免把正文做成画册。

### 3. 多平台封面

用户要求文章封面时，按 `references/multi-platform-cover-workflow.md` 执行：

- 从全文提炼一个封面级核心隐喻，不把多个章节压成信息图。
- 生图前搜索文章 workspace 中的 `assets/icons/`、`assets/icons-drag-ready/` 等素材目录；画面涉及具体产品时，优先把匹配的产品图标作为参考图传入，使用图标而不是把产品名写成文字。优先产品图标，其次才是厂商图标；不要凭记忆发明或改造官方标志。
- 先生成无大标题的统一视觉母版；默认让平台自身显示文章标题。
- 输出微信公众号头条 `900×383`、公众号次条 `500×500`、X Articles `1920×368`、知乎 `1380×560` 四个 PNG。
- 只做覆盖式裁切和缩放，禁止拉伸。裁切会破坏青十五、核心物件或动作时，使用同一视觉方案重排后再裁切。
- 公众号次条必须在 `200×200` 预览下检查；横版母版裁成方形后主体过小或动作残缺时，生成同概念方形重排源图。
- 用户要求带标题时，优先使用确定性本地排版写入精确文字；不要依赖生图模型拼写长中文标题。
- 默认不修改文章正文；只有用户明确要求时才插入封面链接或写入 frontmatter。

### 4. 单张正文配图

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，不要停下来等确认；用内置 `image_gen` 每张单独生成。每次都把 `assets/ip-reference/qing-shiwu-avatar.jpg` 作为角色参考图传入，不要把多张图拼在一张里。

每张图只讲一个核心结构。提示词必须包含：

- 16:9 横版中文正文配图
- 纯白背景
- 黑色手绘线稿
- 少量红色/橙色/蓝色中文手写批注
- 大量留白
- 青十五作为核心动作主体，严格保持参考图身份且只出现上半身
- 禁止 PPT、商业插画、幼稚可爱、复杂架构、左上角类型标题

不要复刻过往案例。每次都要从当前文章重新发明一个奇怪但成立的隐喻。不要为了适配构图而把青十五改成全身、长腿角色、实心黑色角色或普通人形；让角色从画面边缘、桌后、机器后或物件中露出上半身，用细手臂完成动作。

### 5. 检查与迭代

生成后检查 `references/qa-checklist.md`。如果出现以下问题，优先重生成或局部编辑：

- 青十五只是装饰，或没有承担核心动作
- 青十五被画成全身、出现腿，或与参考图的轮廓和五官明显不一致
- 画面太满
- 太像流程图/PPT
- 中文太多或错字严重
- 左上角出现“常见坑/流程图/系统架构图”等标题
- 画风太可爱、幼稚、死板
- 背景不是干净白底
- 封面像素尺寸不精确，或平台裁切后核心动作残缺
- 公众号次条缩到 `200×200` 后角色、主物件或产品图标无法识别
- 有可靠产品图标素材却仍用产品名文字代替，或官方图标形状明显走样
- X Articles 版本只是把普通构图压扁，或超宽裁切只剩角色/物件的一部分

### 6. 保存交付

处理 Markdown 文章时，在文章文件同目录下建立以文章文件名（不含 `.md`）命名的资产目录。正文配图保存到：

```text
<article-dir>/<article-stem>/illustrations/
```

按顺序命名：

```text
01-topic-name.png
02-topic-name.png
```

保留原始生成文件，不要覆盖已有资产，除非用户明确要求替换。

多平台封面保存到同一文章资产目录：

```text
<article-dir>/<article-stem>/covers/
├── cover-master.png
├── cover-x-source.png                    # 仅需要超宽重排时
├── cover-wechat-secondary-source.png     # 仅需要方形重排时
├── cover-wechat-primary-900x383.png
├── cover-wechat-secondary-500x500.png
├── cover-x-article-1920x368.png
└── cover-zhihu-1380x560.png
```

如果用户只粘贴正文、没有可定位的文章文件，优先采用用户指定目录；没有指定时只生成预览并请用户决定项目内保存位置，不要擅自写到与文章无关的目录。

## 输出口径

生成前的策略输出要短而准。生成后的交付要包含：

- 生成了几张
- 每张图的用途
- 保存路径
- 如果使用多平台封面模式：母版与四个成品的尺寸、X 和公众号次条是否发生独立重排
- 如果使用文章标记模式：更新了哪个文章、替换了几个标记、是否仍有未处理标记
- 哪些图最稳，哪些图是可选

不要长篇解释风格理论；让图自己说话。
