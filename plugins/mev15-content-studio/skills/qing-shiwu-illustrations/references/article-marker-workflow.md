# Markdown 文章标记工作流

## 默认触发

用户只调用 `$qing-shiwu-illustrations` 并给出一个 Markdown 文章路径时，先扫描文章中的配图标记。找到标记后，默认完成“理解上下文 → 逐张生图 → 保存 PNG → 插入相对 Markdown 图片链接 → 删除已处理标记”的完整动作，不再要求用户重复说明。

用户的显式要求始终优先。遇到“只规划”“先不要生图”“不要修改文章”“只生成不插入”等要求时，停用相应默认动作。

## 识别标记

识别以下占据整行的标记，允许行首和行尾有空白。

HTML 注释：

```text
<!-- illustration -->
<!-- illustration: optional hint -->
<!-- image -->
<!-- image: optional hint -->
<!-- 配图 -->
<!-- 配图：可选提示 -->
<!-- 插图 -->
<!-- 插图：可选提示 -->
```

方括号标记：

```text
[illustration]
[illustration: optional hint]
[配图]
[配图：可选提示]
【配图】
【配图：可选提示】
[[配图]]
[[配图：可选提示]]
```

英文关键词不区分大小写。提示分隔符接受半角冒号 `:`、全角冒号 `：` 或短横线 `-`。

只把“整行仅包含标记关键词和可选提示”的内容当作标记。不要把普通正文中的“配图”“插图”“image”等词、已有 Markdown 图片、HTML `<img>`、代码块里的示例或引用块里的示例误判为待处理标记。

## 扫描与理解

1. 读取全文，而不是只读取标记所在行。
2. 忽略 YAML frontmatter、围栏代码块和引用块中的伪标记。
3. 按文章顺序记录每个真实标记、所在章节、前后 3-5 个自然段和可选提示。
4. 综合全文主旨、最近的章节标题、局部上下文和标记提示，为每个位置确定一个认知锚点。
5. 多个标记不要重复解释同一观点；让每张图在全文中承担不同作用。
6. 标记提示只提供方向，不替代上下文理解。例如 `<!-- 配图：信任建立 -->` 仍要结合全文判断具体隐喻。

## 生成与保存

1. 每个标记单独调用一次 `image_gen`，不要把多张图拼在一张里。
2. 每次传入 `assets/ip-reference/qing-shiwu-avatar.jpg`，并遵循角色、提示词和 QA 参考文件。
3. 优先使用用户指定的输出目录；没有指定时，在文章文件同目录建立以文章文件名（不含 `.md`）命名的资产目录，并保存到 `<article-dir>/<article-stem>/illustrations/`。
4. 例如 `articles/my-post.md` 对应 `articles/my-post/illustrations/`。文章名包含中文、空格或连字符时默认原样保留，只移除最后的 `.md` 扩展名。
5. 按标记顺序命名为 `01-topic-name.png`、`02-topic-name.png`。不要覆盖已有资产；名称冲突时使用语义清晰的版本化文件名。
6. 生成后先执行 QA。只有文件已保存且通过检查，才允许修改对应文章标记。

## 插入 Markdown

1. 为每张图写一句简短、描述核心意思的中文 alt text。
2. 从文章文件所在目录计算到图片文件的真实相对路径，不要假设文章与 workspace 同级。
3. 用一行标准 Markdown 图片语法替换原标记：

```markdown
![信息从混乱收拢成下一步](my-post/illustrations/01-information-to-action.png)
```

4. 保留标记前后的段落、空行、标题和其他格式，只替换标记本身。
5. 不要留下已成功处理的标记，也不要同时保留标记和新图片链接。
6. 某张图生成、保存或 QA 失败时，保留对应标记原样，继续安全处理其他标记，并在交付中报告失败原因。
7. 修改完成后重新读取文章，确认图片链接存在、相对路径可解析、标记数量符合预期，并避免重复插入。

## 无标记与重复运行

- 没有识别到标记时，不要自行挑选位置，不要修改文章；报告支持的标记格式。
- 已被图片链接替换的位置不再视为标记。重复运行时只处理新出现的标记。
- 标记旁边已经存在明显对应的图片链接时，跳过该标记并报告，避免重复生成。

## 交付报告

简要报告：

- 读取的文章路径。
- 找到、成功替换和未处理的标记数量。
- 每张图的核心用途和保存路径。
- 更新后的文章路径。
- 仍需人工确认的图片或标记。
