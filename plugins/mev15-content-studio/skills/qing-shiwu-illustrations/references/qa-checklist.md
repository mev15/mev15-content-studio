# QA Checklist

## 必过项

- 正文配图是 16:9 横版；封面则与目标平台的精确像素尺寸一致。
- 背景是干净白底。
- 有青十五，并使用 `assets/ip-reference/qing-shiwu-avatar.jpg` 校准角色身份。
- 青十五保持纯白圆润上半身、黑色不规则轮廓、不对称点眼、短斜眉和细手臂。
- 只出现上半身，没有腰部以下、腿、脚或完整站立身体。
- 青十五通过手臂、视线或上半身姿态承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 青十五身体保持纯白，黑色只用于轮廓、五官和手臂。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 青十五变成全身角色，出现腰、腿、脚或站立姿势。
- 青十五变成实心黑色角色、普通人形、动物、雪人或规则胶囊形。
- 青十五失去不对称点眼和短斜眉，或新增夸张嘴巴、服装和闪亮眼睛。
- 青十五像吉祥物、表情包或过度可爱的儿童卡通。
- 无关主题却重复画出参考头像中的水果。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和任何旧案例的构图过于相似。
- 封面被拉伸、压扁，或尺寸与平台预设不一致。
- 公众号次条 `500×500` 成品缩到 `200×200` 后，角色、主物件或核心动作不可辨认。
- 文章或 workspace 已有可靠产品图标，却仍用产品名文字代替图标，或把产品/厂商图标用错。
- X Articles 超宽裁切破坏角色、主物件或核心动作。

## 迭代方法

- 太普通：让青十五用细手臂和上半身姿态成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 restrained、focused、deadpan、not mascot-like，并保持参考图的不对称点眼和短斜眉。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 角色走样：重新传入参考头像，强调 pure-white rounded upper body only、asymmetrical dot eyes、short slanted eyebrows、no legs、no full body。
- 太像旧案例：保留核心意思，换掉主物件和青十五的手臂动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。
- 产品标识不准：重新搜索本地产品图标，优先传入产品级图标参考；产品已合并或更名时遵从用户指定的当前标志。不要靠文字标签补救。
- 方形次条过小：按同一隐喻做方形重排，放大角色、主物件和必要图标，再裁成 `500×500`。
- 封面裁切失败：先调整焦点；仍破坏核心动作时，按同一概念重排对应平台源图。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。
